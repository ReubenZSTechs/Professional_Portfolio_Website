## The problem

General-purpose chatbots are good at everything and expert at nothing. I wanted assistants that each do one job well, run on my own hardware, and share infrastructure so a new agent doesn't mean rebuilding the stack.

A.T.H.E.N.A is the umbrella for six agents, each with its own repository:

| Agent | Role |
|---|---|
| [**Arthur**](/projects/arthur-research-paper-summarizer) | Research-paper summariser and Q&A |
| [**Tasya**](/projects/tasya-personal-finance-agent) | Personal finance: budgeting, analysis, Q&A |
| **Harper** | Career and opportunity hunter: searches and filters jobs for a user persona |
| [**Elena**](/projects/elena-research-knowledge-base) | Research-paper knowledge base for future research |
| [**Nash**](/projects/nash-theology-assistant) | Theology assistant (Reformed perspective) |
| **Alena** | Daily-life assistant and day planner |

## How it works

<Pipeline steps={["Agent repo from shared template", "Backend (FastAPI + LangGraph)", "Fine-tune (LoRA)", "Merge → GGUF → Ollama", "Docker + nginx deploy"]} highlight={3} />

Every agent starts from the same workspace template: `backend/` (API, core, services, pipelines, retrieval, models, database, configs), `frontend/`, `training/` and `deployment/`. The shared training utilities take a LoRA adapter through the whole path to local serving: **merge the adapter → convert to GGUF with llama.cpp → generate a Modelfile → register and verify the model in Ollama**. Deployment is containerised: backend, frontend and Ollama behind nginx, with ngrok for remote access and scripts to start, stop, rebuild and deploy.

## Key decisions

<Decisions>
  <Decision title="One template, many agents">
    A shared folder structure and deployment stack means each new agent only adds its own graph, prompts and data, so platform fixes reach every agent.
  </Decision>
  <Decision title="Local-first models">
    Fine-tuned models are exported to GGUF and served through Ollama, or through vLLM on agents that need structured decoding. Personal data such as finances never leaves my machine, and there are no per-token costs.
  </Decision>
  <Decision title="Specialists over a generalist">
    Each agent gets a narrow role, its own retrieval sources and its own evaluation. That's easier to test and improve than one model that does everything.
  </Decision>
</Decisions>
